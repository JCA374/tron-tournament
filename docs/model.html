The five contestants

Five different answers to the same question: how can a program get good at a game nobody explained to it? Two learn from rewards (PPO, DQN), two evolve (NEAT, CMA-ES), and one plans ahead with search (Mini-AlphaZero). Each gets the same observation (see How it sees), the same CPU share and the same two days. Below each description is its own training curve, straight from its log file.

PPO: Proximal Policy Optimization

What it is: a neural network (the 675 window values + 23 numbers → 256 → 128 → 3 move probabilities + 1 value estimate) that plays 64 games at once. After every 128 moves in each game (8,192 moves), it nudges the network so moves that turned out better than expected become more likely, and those that turned out worse less likely. The "proximal" part: no move's probability may change by more than 20% in one update, which keeps learning stable.

What it's paid for: +1 for a win, −1 for a loss, 0 for a draw. Nothing else: no reward for surviving or for space.

Who it plays: 80% of the time an older copy of itself (a pool of the last 12 snapshots, one saved every 25 updates), 15% the space-filler bot and 5% the avoid-walls bot. Playing old selves rather than only the newest avoids going in circles.

Expected: steady, reliable progress; it's the method most game-playing RL starts from.

DQN: Deep Q-Network (double, dueling, 3-step)

What it is: the same size of network, but it outputs a value for each move: "how much will I win from here if I go left / straight / right?". It plays the move with the highest value, except a shrinking fraction of random moves (100% at the start, 3% after 1.5 M moves) to keep exploring.

How it learns: every move goes into a memory of the last 150,000. After each step of its 32 games it re-studies 256 random memories, so it learns from the same experience many times, unlike PPO. Double: a slow-moving copy of the network judges the next position, which stops it fooling itself with over-optimistic values. Dueling: the network learns "how good is this position" and "how much better is each move" separately. 3-step: it looks at the actual rewards over the next three moves before trusting its own estimate.

Who it plays: like PPO, old copies of itself and the bots. Expected: very efficient with experience but can be unstable.

NEAT: NeuroEvolution of Augmenting Topologies

What it is: a population of 120 tiny networks. They start with only direct connections from the 23 numbers to the 3 moves, and evolution may add neurons and connections over time. There's no gradient and no backpropagation: networks that win more games have more children, and children are mutated copies (weights changed, a connection added, a neuron inserted, or crossovers of two parents).

Species: networks are grouped by how similar their structure is, and compete mostly within their group. A new structural idea gets a few generations to prove itself before it has to beat the established champions.

Fitness: each network plays 10 games per generation: 4 against space-filler, 2 against avoid-walls, and 4 against the last six generations' champions (the same games for everyone, so it's a fair comparison). Score: win 1, draw ½, plus a tiny bonus for surviving long.

Expected: a slow start, odd-looking playing styles, and networks small enough to read.

CMA-ES: Covariance Matrix Adaptation Evolution Strategy

What it is: a fixed small network (23 numbers → 32 neurons → 3 moves, 899 weights). Instead of one network it keeps a cloud of possible weight settings: a centre and a shape. Each generation it samples 32 networks from the cloud, has them play the same 10 games as NEAT, then moves the centre toward the winners and stretches the cloud in the directions that worked. That "covariance" is what makes it smart: it learns which weights should change together.

Expected: robust and cautious play; often surprisingly strong on small networks. Its playing model is always the cloud's centre.

Mini-AlphaZero: tree search + a learned network

What it is: before every move it thinks ahead. It builds a tree of possible futures by trying moves in a copy of the game (48 simulations per move while training, 32 in the tournament). A network (same shape as PPO's) suggests which moves are worth exploring and guesses who's winning in positions it doesn't search further.

The twist for Tron: chess and Go are turn-based, but here both bikes move at once. So each position in the tree keeps separate statistics for each bike ("decoupled" search), and the next position depends on both bikes' moves.

How it learns: only from self-play. After each game the network is trained to predict (a) the moves the search ended up preferring and (b) who won. Better network → better search → better training data.

Expected: strong from the start, because search with an exact copy of the rules catches immediate traps. But every move costs ~32 network calls, so it plays far fewer games than the others (about 1,200 an hour on one core, against PPO's ~15,000).
